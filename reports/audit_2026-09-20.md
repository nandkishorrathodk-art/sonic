Auditor: OpenHands agent. Method: manual line-by-line review of 64k LOC with live
reproduction of each issue against the real code paths (no mocks used to "prove" a

Severity legend: **CRITICAL** = safety/truthfulness invariant broken with a working

## CRITICAL

### C1. Seal hash does not cover the live scope rules → runtime scope widening is undetected (Rule 11, 13, 18)
`sonic/safety/sealed.py:184-236` (`_compute_seal_hash`), `sonic/safety/action_policy.py:290-320` (`_get_active_scope_config` / `_check_target_and_scope`), `clone_for_agent` at `sealed.py:157-181`.

`SealedActionPolicy` hashes only `scope_config` (a copied dict) plus *class-level*
pattern lists. But scope enforcement at evaluate-time reads the **live**
`scope_checker._rules` / `scope_checker.scope_config`, and `clone_for_agent` shares
the **same mutable `ScopeChecker` object** with every sub-agent. Mutating the live
checker widens/tightens what `evaluate()` permits while the recomputed seal hash is
**unchanged** (proven):

```
seal hash unchanged after mutating live scope rules: True
is_seal_valid-style compare: True
clone shares scope_checker object: True
```

So the "self-evolving being cannot widen its own guards" guarantee of Rule 11 does
not hold for the most important guard (target scope). Impact: a self-evolving being
(or in-process code) can add `*` to the engagement scope and the sealed policy will
still verify as intact.

### C2. Cross-tenant data overwrite / update / delete in SQLite graph memory (Rule 17)
`sonic/memory/sqlite_graph.py:161-221` — primary key is `uid TEXT PRIMARY KEY`
(not `(tenant_id, uid)`), and `_update_node` / `_delete_node` use
`WHERE uid = ?` with **no tenant_id predicate** (the tenant check is only done on
the pre-read, then ignored in the mutation). Reproduction with two tenants writing
the same node uid:

```
tenantA: None            # tenant A silently overwritten by B's write
tenantB: {'note': 'B', ...}
```

Impact: if two tenants ever use the same uid / host identifier ("web-01",
"10.0.31.7", a user-chosen engagement id), tenant B silently destroys tenant A's
node (`INSERT OR REPLACE`), and either tenant can update/delete the other's data
(`DELETE ... WHERE uid = ?`). Direct Rule 17 ("phantom states"/tenant isolation)
violation and an IDOR at the persistence layer.

## HIGH

### H1. Cloud-metadata guard in `TERMINAL_EXEC` is trivially bypassable (Rule 11, 13)
`sonic/safety/action_policy.py:236-278` (`_CLOUD_METADATA_RE` + `_check_command`).
The regex only matches the literal string `169.254.169.254` (and provider
hostnames). Every semantic equivalent is allowed:

```
hex-encoded url      allowed=False   (caught only because it is inside a URL)
dword url            allowed=False
base64 pipe          allowed=True    <-- `echo aHR0cDovLzE2OS4yNTQuMTY5LjI1NC8= | base64 -d | sh`
curl -K config       allowed=True    <-- URL loaded from a config file, never in the string
```

Because `TERMINAL_EXEC` deliberately bypasses URL egress (the code comments say so),
the only thing protecting the metadata endpoint from a shell command is a literal
substring match — trivially defeated with base64/`curl -K`/variables. Rule 13
requires egress to fail closed on every action; it does not.

### H2. Fork bomb and common destructive commands classify as L0 (safe) (Rule 11)
`sonic/safety/scope.py:171-193` (`_DESTRUCTIVE_PATTERNS`). Proven L0:

```
:(){:|:&};:        -> L0     # the fork-bomb pattern in the list expects spaces and never matches
chmod -R 777 /     -> L0
cat /etc/shadow    -> L0
```

The fork-bomb regex `:\(\)\{\s*:\|:&\s*\};:` requires a space that the canonical
one-liner does not contain, so the sole fork-bomb rule is dead code.

### H3. Judge confirms a goal from an irrelevant successful command (Rule 15, 19)
`sonic/agents/judge.py:276-283` (`has_concrete_proof and result.success`). The
"default grounded verdict" treats *any* trace with exit 0 / non-empty output as
empirical proof of the sub-mission, with no relevance check to the goal. Proven:

```
goal: "obtain valid credentials for the admin panel"
trace: `ls -la` exit 0
=> verdict: CONFIRMED  confidence: 0.85
   notes: "Empirical execution verified: Non-trivial command executed with exit 0..."
```

This is exactly the "success by decree" Rule 15 forbids — a worker that ran an
unrelated command is graded CONFIRMED. (Note: identity plumbing *is* correct —
`boss.py:1036-1040` passes `worker_agent_id=sub_agent_id` — so the defect is the
relevance check, not self-attestation.)

### H4. Milestones falsely marked COMPLETED by keyword overlap, not by the required action (Rule 15)
`sonic/mission_engine/trace_synthesis.py:214-236` (`_milestone_matches`). The
heuristic buckets milestones by keywords in `success_conditions`; a "Remediate /
patch" milestone completes on **either** FILE_WRITE **or** GIT_COMMIT, and the
catch-all completes any milestone on any successful action. Proven with a single
`GIT_COMMIT` and no patch:

```
ms1 (Remediate, conditions ["apply patch","remediation"]): COMPLETED
ms2 (Commit): COMPLETED
```

Rule 15 requires a milestone to be COMPLETED only when traces contain evidence
*relevant to that milestone's success conditions*; the `or "GIT_COMMIT"` and the
`"test"`/`"verif"` keyword sharing make a "fix + test + verify" milestone complete
on a single commit/file-write.

### H5. Evolution safety-invariant guard is bypassable by path spelling (Rule 11)
`sonic/evolution/codebase_evolver.py:181-189` (`is_protected`) uses substring
matching on a lightly-normalized string. Proven non-protected spellings of a
protected file:

```
sonic//safety/action_policy.py     protected=False
sonic/./safety/action_policy.py    protected=False
```

Meanwhile `apply_patch` resolves the path with `Path(...).resolve()` before writing
(`codebase_evolver.py:243`), so the *write* lands on the real safety file even
though the *guard* said it was safe. Combined with H6 this is the exact safety-
envelope-widening vector Rule 11 forbids.

### H6. Autonomous evolution auto-commits by default (`auto_promote=True`) (Rule 21, 11)
`sonic/evolution/engine.py:202-226` and `:250-266` default `auto_promote=True`, and
`execute_evolution_goal` is invoked with the default. Guarded only by pytest
passing (which is environment-sensitive). This auto-commits agent-authored diffs
to the repository working tree without human approval; `push=True` is reachable
from the CLI (`sonic/evolution/cli.py:188`, `goal_director.py:600`).

### H7. Hardcoded chromium browser-profile probe in core control flow (Rule 1)
`sonic/computer/docker_computer.py:941-948`:
```
f"readlink -f {shlex.quote(resolved_bin)} | grep -qiE 'chrome|chromium|electron|brave|edge' || ..."
```
Rule 1 explicitly forbids string-matching binaries against a fixed list of known
proprietary application names and forbids writing prompt/code that biases toward a
particular browser. The app *is* discovered dynamically, but then special-cased by
a hardcoded name list — a direct violation.

### H8. Detection paths use IPv4-only DNS (Rule 13)
`sonic/sandbox/egress.py:171` (`socket.gethostbyname_ex`, A records only),
`sonic/api/routes/workstation.py:1156-1157` and `sonic/agents/engagement.py:170`
(call `is_target_allowed`). A target that resolves only to an AAAA (IPv6) address
is treated as "DNS failed": at engagement creation with `allow_unresolvable=True`
it is **allowed** (private/metadata IPv6 never checked); elsewhere it fails closed.
Inconsistent and a genuine IPv6 leak path for the creation flow. (`browser/container_runtime.py:154` correctly uses `getaddrinfo`; `egress.py` does not.)

## MEDIUM

### M1. "\*.example.com" does not match the bare apex `example.com` (Rule 3)
`sonic/safety/scope.py:240-330` + `_domain_to_regex`. Proven: `targets:
["*.example.com"]` yields `example.com -> False` (everything else correct:
`evil.example.com.attacker.net -> False`, exclusions honored). If a program lists
only `*.example.com` while meaning the apex too, the apex is silently out of scope.

### M2. `allow_private_for_tests=True` is an unconditional egress bypass (Rule 11)
`sonic/sandbox/egress.py:104-105`: `if allow_private_for_tests: return True,
"Allowed (test override)"` — no dev/test environment assertion. Not currently
reachable from production (only `action_policy._check_egress` passes it, and only
when `allow_private_networks` is set), but the flag name and lack of a guard make
it a latent fail-open footgun.

### M3. Windows-absolute paths are "confined" and forwarded to the sandbox (Rule 11)
`sonic/safety/action_policy.py:_check_path`. Proven:
`_check_path("C:/Users/root/.ssh/id_rsa") -> allowed=True, "path confined"`.
POSIX `Path(...).is_absolute()` is False for drive-letter paths, so they are joined
under the workspace root. A remote (possibly Windows/Samba-backed) provider could
interpret `C:/...` as a host-absolute path, escaping the intended confinement.

### M4. Terminal-metadata regex is over/under-inclusive (Rule 13)
`_check_command` blocks any command merely *containing* the metadata IP (e.g. a
comment), while missing `169.254.169.253/…` variants already covered by egress but
not by the string check; combined with C1/H1 the terminal path is the weakest link.

## LOW / hygiene

- **L1.** `sonic/api/routes/security.py:134-136`: the self-audit "SEC-HOST-01"
  probe is `verdict = "PASS" if hasattr(ActionPolicy, "is_allowed") else "PASS"`
  — always PASS; a tautological self-test (Rule 15 spirit).
- **L2.** `sonic/auth/google_auth.py:135-243`: `/auth/google/callback` places the
  JWT in a redirect URL query string (leaks via Referer/logs/browser history);
  prefer a fragment or one-time code exchange. JWT decode is correct (verify sig +
  exp) and production refreshes a weak `CHANGE-ME` secret (C3 avoided), but
  `app_env` defaults to `development`, so a misconfigured prod boot is dev.
- **L3.** `sonic/api/routes/llm.py:54-100`: `/llm/chat` accepts `images[].url`;
  verify the provider cannot be pointed at an internal URL (SSRF). `provider`/
  `model` are restricted to configured providers (no arbitrary base_url), which
  limits the blast radius.
- **L4.** Dead code: `ScopeChecker.is_egress_allowed` (`scope.py:303`) and
  `has_active_scope_rules` have **no production callers**; the YAML
  `network_policy.always_allowed` list is loaded but never enforced. Rule 13's
  "egress boundary checks through ActionPolicy" rely solely on the ip literal
  checks.
- **L5.** `sonic/memory/sqlite_graph.py:220`: `_delete_node` deletes relationships
  by uid only, so it also removes the *other* tenant's relationships touching that
  uid (see C2).
- **L6.** `sonic/computer/daytona_computer.py:661-667` writes screenshots to a
  static `/tmp/sonic_screen.png`, violating Rule 20's unique-path mandate (the
  Docker provider already uses `sonic_screen_{uuid}.png`); concurrent Daytona
  captures can clobber each other.
- **L7.** Anti-stall "zero screen change" compares `pre_screen_b64 == post_screen_b64`
  after calling `draw_action_marker(...)` on the pre-frame but not on copying the
  crosshair into the post-frame's stored copy; the comparison still works because
  the marker is only applied to `_last_screenshot_b64`, but review with care if the
  marker ever moves.
- **L8.** `ruff` reports 6 `F541` (f-string without placeholders) — trivial.
- **L9.** `_INTRUSIVE_PATTERNS` have no space-variant normalization (unlike the
  destructive patterns, which correctly try both raw + normalized candidates), so
  `simple` obfuscation of `nmap -sS`/`hydra` etc. moves L1→L0.
