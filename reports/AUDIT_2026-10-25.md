## 2. Security

### Auth coverage — strong
- **148 auth-guarded call sites across 144 routes.**
- Only **7 routes lack an auth dependency**, and every one is expected:
  `POST /login`, `POST /dev-token`, `GET /google/{config,login,callback}`,
  `GET /health`, `GET /health/detailed`.
- `POST /dev-token` is **hard-gated to `app_env == "development"`** and can never
  elevate to `SUPER_ADMIN` / `TENANT_ADMIN`.
- Google OAuth callback **verifies `state` via `consume_oauth_state()`** (CSRF
  protection) and confines the post-login redirect to same-origin relative paths
  (no token exfiltration via open redirect).

### Secrets hygiene — clean
- No hardcoded credentials in source. `.env`, `*.db`, `sonic_data/`, `*.pt` all
  gitignored.
- Strings matching secret patterns in git history are **test fixtures** in
  `apps/cli/tests/test_developer_agent_safety.py` (deliberate sanitizer tests),
  not real keys.

### Safety envelope — wired in production, not just tests
- `SealedActionPolicy` (`seal_default`) is constructed in the being life loop
  (`api/main.py:111`), `MissionDirector`, `EngagementManager`, and the
  workstation route. Seal hash is recomputed and verified on every `evaluate()`.
- **Egress filter is applied to `SECURITY_TOOL`, `TOOL_RUN`, `METHOD_INVENT`,
  `BROWSER_NAVIGATE`, and `GIT_PUSH`** — the previously-flagged toolsmith
  arbitrary-egress gap is closed.
- Egress blocks RFC1918, loopback, cloud metadata (`169.254.169.254`), IPv4-mapped
  IPv6, and NAT64 forms.

### Previously-flagged gaps — now verified fixed
| Prior finding | Status |
|---|---|
| `kill_switch` declared but never enforced | **Fixed** — enforced in `mission_engine/executor.py`, `queue/worker.py`, `safety/action_policy.py` |
| `/var/run/docker.sock` mounted in prod | **Fixed** — not present in either compose file |
| No resource limits on prod services | **Fixed** — `deploy.resources.limits` set (cpu/mem) |
| Toolsmith LLM-authored code had no egress check | **Fixed** — policy now gates TOOL_RUN/METHOD_INVENT targets |

### Docker posture — good
- `sandbox-kali` / `sandbox-debian`: `no-new-privileges:true`, resource limits,
  isolated networks. No `privileged:true`, no host-root bind mounts.

## 3. Boss / subagent visibility (the operator's original concern)

**Wired end-to-end, verified in code.**
- `SubMission` carries `id`, `name`, `goal`, `role`, `status`, `plane`,
  `depends_on`.
- Boss registers each sub-mission as a `TaskNode` and dispatches with
  `agent_id = f"sub-agent-{n}"`.
- The workstation route streams `sub_dispatch`, `sub_step`, `sub_report`,
  `phase_complete`, `boss_report` events, each carrying `agent_id` /
  `sub_agent_id` / `sub_agent_uid`.
- The dashboard (`WorklogFeed.tsx`) groups by `agent:${agent_id}` and renders a
  per-worker drill-down card.
- Background liveness: `dispatched_count` vs `planned_count` is surfaced so the
  UI cannot report a phantom completion.
